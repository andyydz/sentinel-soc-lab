## 4. Suite C — SSH Brute Force (`100200–100201`)
- **How the threshold counts:** Rule `100200` matches more than distinct failed-password attempts; the committed records include `Invalid user`, `Disconnected from invalid user` (pre-authentication) and `Failed password` events. Rule `100201` uses `<if_matched_sid>100200</if_matched_sid>`, `frequency="6"`, `timeframe="60"` and `<same_srcip />`, so its threshold is six matching Rule `100200` events from the same source IP within the window. It does not establish six distinct password guesses or six distinct authentication attempts.
- **C1 (2 Hydra tries, `v06-benign-check`, `14:44:09.561Z`):** `4x 100200` (`Invalid user` + `Disconnected [preauth]`/`Failed password`), `0x 100201` (below threshold). Four Rule `100200` matches across two Hydra tries.
- **C2 (10 Hydra tries, `v06-pt-probe`, `14:45:00.550Z`):** `8x 100200`, `2x 100201`:
  - 1st `100201` (`14:45:03.882Z`, `3.332s`): occurred after two additional C2 `100200` matches combined with the four earlier C1 `100200` matches still inside the `60s` window (`4 + 2 = 6` matching events). This is not proof of six distinct failed password attempts.
  - 2nd `100201` (`14:45:09.893Z`, `9.343s`; `6.008s` after 1st C2 `100200`): triggered by C2 burst. As with the first, this reflects matching Rule `100200` event counts, not necessarily unique login attempts.
